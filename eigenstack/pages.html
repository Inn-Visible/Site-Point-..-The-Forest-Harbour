the practical part · what to learn — OS & languages
covered: 4f · 4b · 5f · 5b
  • 1. operating systems (worth $$$): tier 1 — non-negotiable: Linux (Ubuntu / Debian-based) — runs everything behind smart homes, routers, panels, servers. you don’t need kernel hacking (—yet—). you need: filesystem · services · logs · permissions · SSH. if you can install linux · read logs · restart services · edit config files → you’re already ahead of most techs.
  • tier 2 — optional but useful: Windows (diagnostics software, vendor tools). NB!! skip macOS unless you’re forced.
  • 2. programming languages — “this matters, but not how people sell it.” you do not want “software engineering language” ↳ you want glue languages.
  • tier 1 — [absolute priority] = Python · diagnostics · automation · scripts · raspberry pi · IoT tooling · reads in english · bridges hardware/software. what you need: read sensor data · parse logs · talk to APIs · control devices — not leetcode, not web apps. margin: “if you learn only one language: this is it.”
  • tier 2 — system-adjacent: Bash — not a ‘language’ so much as survival skill · inspect systems · chain commands · automate fixes. “you don’t ‘study’ bash — you absorb it.”
  • tier 3 — conditional: JavaScript (dashboards/web UIs) · C (deep embedded later). you can safely ignore: Java · C++ · Rust · Swift {for now...}.
hardware · the one concept · the concrete stack
covered: 6f · 7f · 8f · 8b
  • 3. hardware work — what’s actually viable: a modern house is becoming: sensors · controllers · actuators · networks · power → that means [hybrid hardware], (not solder-microscopes all day). viable domains: power supplies · motors · relays · control boards · sensors (temp, motion, current) · networking hardware · interfaces (USB, serial, CAN, Ethernet). “you’re not replacing chips — you’re diagnosing why systems stop cooperating.”
  • 4. the single most important concept: [control systems] — the overlap of electricity · logic · feedback · safety. shows up as: thermostats · HVAC · elevators · washing machines · smart lighting · industrial panels. “this is where electricians stop & millwrights continue.”
  • concrete learning stack (‘no fluff’): phase I — foundation (you’re already here): open broken devices · identify components · guess failure points · read part numbers · look up datasheets. phase II — control + linux: raspberry pi · linux basics · python: read inputs ⇄ trigger outputs · (this turns ‘fixing’ into ‘understanding’).
  • phase III — smart building layer: Home Assistant · MQTT · Modbus (IMPORTANT) · basic networking (IP, ports) · at this point you can walk into a “smart home” & not panic. phase IV — commercial crossover: PLC concepts · safety logic · documentation · fault tree · now you’re approaching millwright-lite territory.

stack 6 · infrastructure
covered: 27f · 27b · missing: 26f · 26b
  • “if you want a real education in this, read these in order.”
  • 1. Seeing Like a State — James C. Scott
    foundational. it explains: why systems flatten reality · why infrastructure simplifies humans · why legibility = power.
    margin: “this book will change how you see everything.”
  • 2. The Power Broker — Robert Caro
    not about a man. about how infrastructure becomes destiny. you’ll see: how control hides behind “public good” · how permanence beats popularity · how power accumulates quietly.
  • 3. Infrastructure: A Field Guide — Brian Larkin
    more academic, but explains: how infrastructure shapes behavior · why invisible systems dominate · how culture follows pipes & wires.
  • 4. The Utopia of Rules — David Graeber
    explains bureaucracy as a power structure. very relevant to modern life.
  • 5. Platform Capitalism — Nick Srnicek
    explains how modern infrastructure = data + coordination. (this explains Uber, Amazon, Google, etc.)
